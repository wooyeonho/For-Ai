## 1. What changed and why

G9 is the first gate where YENO is allowed to point at its own source. The dangerous version of this
feature writes files; the honest version records a claim and then refuses every step towards acting
on it. This RUN builds the ledger and the refusals, and deliberately does not build the apply path.

The ladder a self-authored change must climb, and who owns each rung:

```text
PROPOSED      YENO           bytes in the vault, a rationale, a blast radius, a rollback
BENCHMARKED   measurement    at least one improvement on *these exact bytes*, no regression
APPROVED      the Owner      a live grant for evolution.apply on this path, bound to the diff hash
APPLIED       nobody yet     refused: no sandbox, no canary, no automatic rollback exists
```

New in this RUN:

- `migrations/0018_evolution_lab.sql` — `evolution_forbidden_targets`, `change_proposals`,
  `proposal_benchmarks`, `v_evolution_lab`, and 15 triggers that enforce the ladder in the schema.
- `src/domain/evolution.mjs` — propose / benchmark / promote / approve / reject / report, and an
  `applyApproved()` whose only behaviour is a documented refusal.
- `src/cli.mjs` — `lab propose|bench|benchmarked|approve|reject|apply|report|targets`, plus
  `approval grant --payload-hash` so the Owner can bind consent to a patch's bytes rather than JSON.
- `test/evolution.test.mjs` — 7 tests, each an attempt to skip a rung, through the API *and* raw SQL.
- `scripts/independent-validation.mjs` — `evolution_lab_recomputed`, which re-derives every verdict
  from its own numbers without importing `src/domain/evolution.mjs`.
- `scripts/assert-seeded-defect-detected.mjs` — cases 30–32: the leash removed, then the forbidden
  act performed.

## 2. What YENO cannot do, and where the refusal lives

| Attempt | Refused by |
|---|---|
| propose a change to `migrations/%`, the governor, the event chain, the validators, `CLAUDE.md` | `trg_proposal_target_not_forbidden` (INSERT-time), and the list itself is undeletable from inside |
| be born `BENCHMARKED`/`APPROVED`/`APPLIED`, or born with an `approval_id` | `trg_proposal_starts_powerless` |
| edit the target or the diff hash of an existing proposal | `trg_proposal_identity_immutable` |
| file a benchmark against bytes other than the proposal's | `trg_benchmark_measures_this_diff` |
| record `PASS` while its own numbers got worse (or `REGRESSION` while they improved) | `trg_benchmark_verdict_matches_numbers` |
| improve yesterday's number, or delete an inconvenient benchmark | `trg_benchmark_append_only`, `trg_benchmark_no_delete` |
| reach `BENCHMARKED` with no improvement or with a regression on record | `trg_proposal_benchmarked_needs_measurement` |
| reach `APPROVED` without a live Owner grant bound to the diff hash and citing an Owner Packet on disk | `trg_proposal_approved_needs_owner_approval` (+ `0011`'s Packet-on-disk rule) |
| skip a rung (`PROPOSED → APPLIED`, `PROPOSED → ROLLED_BACK`) | `trg_proposal_state_ladder` |
| apply while the stop is engaged, or on a revoked approval | `trg_proposal_applied_needs_live_approval` |
| delete a proposal | `trg_proposal_no_delete` |
| apply at all | `applyApproved()` returns `APPLY_PATH_NOT_BUILT`; no code writes a patch to disk |

Consent is bound to bytes, not to intent: the approval carries `payload_hash = diff_sha256`, so
editing the patch after approval silently loses the approval instead of inheriting it. Granting is
not part of the lab — the Evolution Lab consumes approvals and cannot mint them.

The last two lines are the point of the whole RUN: the most a self-authored change can reach on this
machine is a row that says it is approved and still cannot run.

## 5. What this is not

G9 is **not** passed, and not only because of gate order:

- No sandbox. An approved patch has never been applied to a copy of the kernel and tested there.
- No canary and no automatic rollback, which is exactly why `applyApproved()` refuses.
- The benchmark registry accepts numbers a caller measured; it does not run the suites itself, so a
  benchmark is only as honest as the `measured_by`/`evidence_ref` behind it.
- No seeded-regression run through a real apply/rollback cycle.
- No performance, cost or safety improvement has been demonstrated *by* a self-change.

Gate order still governs: G2 is `NEEDS_SOURCE` (no official ChatGPT/Claude/Grok export), so G3–G9
remain `PENDING` regardless of the evidence under them. `gate pass --gate G9` refuses.

## 6. Rollback

- Schema: additive only. `0018` creates new tables, triggers and one view; no existing object is
  modified. Reverting the commit plus dropping the three new objects returns the kernel to RUN-018.
- Code: `src/domain/evolution.mjs` is new; the only edits to existing files are additive CLI cases,
  one optional `--payload-hash` flag, and one new validator check.
- State: `state/yeno.db` gained migration 0018 and no rows. All exercises ran on throwaway kernels
  under `/tmp`, which were deleted. The emergency stop was never released on the real kernel.
