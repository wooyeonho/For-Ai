## 1. What changed and why

RUN-015 fixed what the shell may draw. This RUN implements the drawing, minus the pixels: a
renderer needs the contract, the rows, and a rule for what to do when the two disagree — and that
rule is the part a hand-written UI always gets wrong. Tauri is only needed for the pixels, so the
rule can be built and tested today with no install.

`src/ui/render.mjs` turns a contract plus panel rows into **lines of text**, which makes the screen
an assertable value rather than something only a human can check:

```text
renderScreen(contract, panelsData, { refusals })
  -> for each panel the contract promises
       header  = contract columns, in contract order
       rows    = only those columns; anything else in the row has no code path
       buttons = contract actions, disabled with the reason when the kernel would refuse
```

## 2. The four rules, each with a test

| Rule | Why | Test |
|---|---|---|
| A column the contract does not list is never drawn, even when the row carries it | that is the shape of a stale or tampered API response | `a value the contract does not know about cannot reach the screen` |
| A contract column the row lacks is drawn `—` | a skipped cell shifts every column after it, so the Owner reads the wrong value under the right header | `a column the contract lists but the row lacks is drawn as missing, not skipped` |
| Rows from another view are refused, not relabelled | foreign rows under this panel's headers are a lie the Owner cannot see | `rows from a view the contract does not name are refused, not relabelled` |
| A button the kernel would refuse now is drawn disabled with the reason | a button that looks pressable and is not teaches the Owner to distrust the screen | `while the kernel is stopped every button is drawn disabled with the reason` |

`currentRefusals()` asks the kernel's own stop state rather than guessing, so a disabled button is
disabled for the same reason the command would be denied. A fresh kernel is stopped by default,
which is exactly the state a shell meets on first launch, after a restore and after a reboot — so in
that state **every** button on the screen is disabled, and the test asserts it.

Dropping a panel is also an error: `renderScreen` throws when the contract promises a panel and no
rows were served, because a panel that quietly disappears is how an Owner stops seeing approvals.
