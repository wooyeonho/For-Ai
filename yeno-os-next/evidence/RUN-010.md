## The invariant this RUN exists to prove

> when the daemon dies, something else brings it back — with a genuinely new process, deterministic backoff, and a
> refusal to fight a crash loop forever — and each boundary is still served exactly once

RUN-009 restarted the daemon from the soak harness, i.e. the operator was the test. Here a supervisor process owns the
restart decision, and the harness only kills things: the daemon child alone (supervisor survives and must replace it),
the whole process group (nothing survives, so the next fresh supervisor must continue from durable DB state), and a
clean shutdown (nothing may be resurrected).

## What was built

1. `migrations/0015_supervisor.sql` (additive; no existing table touched) — `supervisor_soak_cycles`
   (`death` in `child`/`supervisor`/`clean`, `killed`, `restarts`, `distinct_child_pids`, `ran_ms`,
   `boundaries_served`, `duplicate_boundaries`, `duplicate_jobs`, `fires_regressed`, `ok`, detail) with append-only
   and no-delete triggers, plus an honest-verdict trigger. A cycle may only be recorded as a pass if it really died
   the way it claims, and — for a child death — only if it actually restarted **and** saw at least two distinct child
   PIDs. "I restarted it" with one PID on record is rejected at the SQL level, because that is the exact lie a
   supervisor evidence table invites.
2. `src/domain/supervisor.mjs` — pure decision core, no I/O: `backoffMs()` (200 ms doubling, capped at 5 s) and
   `superviseDecision()`, which returns `stop` on a clean exit (`code 0`, no signal) or when the supervisor is itself
   stopping, `crash_loop` at 5 crashes inside a 10 s window, and otherwise `restart` with the computed delay. A
   nonzero exit with no signal counts as a crash, so a daemon that dies of its own bug is not treated as a clean stop.
3. `scripts/scheduler-supervisor.mjs` — the real supervising process. It owns **no** scheduler authority: it never
   opens the database, never arms a schedule, never touches the emergency stop. It spawns
   `scripts/scheduler-daemon.mjs`, logs `child_started=<pid>` / `child_exit=<pid> code=… signal=…`, forwards
   `SIGTERM`/`SIGINT` to the child, and exits nonzero on a crash loop so an outer supervisor (later: a Windows
   service) sees a failure instead of a silent idle process.
4. `scripts/supervisor-soak.mjs` — the three-death-mode soak. One armed one-second schedule; each cycle spawns a
   detached supervisor **process group** and then kills either the child (`SIGKILL` on the child PID only, requiring a
   replacement PID), the whole tree (`SIGKILL` on the negative PID), or nothing (`SIGTERM`, clean). Duplicates are
   recomputed from raw rows, and a soak where nothing fired is a failure, not a vacuous pass.
5. `scripts/independent-validation.mjs` — new `scheduler_supervisor_recomputed` check, from raw
   `supervisor_soak_cycles` rows: dishonest passing cycles, and whether any recorded soak is clean **and** contains at
   least one child kill, at least one tree kill, at least one unattended restart, and real progress.
6. `scripts/assert-seeded-defect-detected.mjs` — 2 new seeded defects (21 total): a cycle claiming a restart with no
   new process, and a cycle calling a duplicated boundary a pass. Both are seeded by dropping the honest-verdict
   trigger in a throwaway database, so the check proves the *validator* catches the lie, not merely the trigger.
7. `scripts/local-ci.mjs` — `scheduler_supervisor_soak` is now a CI step (18 steps), run with `--no-record` so
   repeated CI runs never add rows to the kernel's soak evidence.
8. `test/supervisor.test.mjs` — 8 tests: backoff grows and caps; a clean daemon exit is obeyed; a `SIGKILL`ed daemon
   is replaced after backoff; a nonzero exit counts as a crash; a crash loop stops supervision; a stopping supervisor
   does not restart; an end-to-end fake crash-looping daemon makes the real supervisor exit nonzero; and the evidence
   table refuses false restart/duplicate claims while accepting an honest failing row and a tree-death row.

## Limitations recorded honestly

- **Still no OS reboot evidence.** Every death here is a process or process-group death. A real Windows/WSL restart
  with the supervisor coming back by itself (autostart, service registration) is G10 work and is not claimed.
- **No service registration.** There is no systemd unit, no Windows service, no scheduled task. The supervisor must
  currently be started by hand; nothing starts *it*.
- **Tree-death cycles restart nothing.** When the whole group is `SIGKILL`ed, continuity comes from the next
  supervisor the harness starts plus durable DB state — that is exactly what the cycle proves, and it is not an
  autostart claim.
- **Nothing is armed in production.** The master switch is `enabled = 0`, the emergency stop is `ON`, and the only
  schedule on the ledger is disarmed. The supervisor cannot change any of those three: it never opens the database.
- **Crash-loop thresholds are policy, not proof.** 5 crashes / 10 s and a 5 s backoff cap are chosen defaults, tested
  for behaviour, not tuned against production data.
- **Soak scale.** 6 cycles, ~14 seconds, 14 boundaries. Enough to break at-most-once per death if it were breakable,
  not a 72-hour endurance claim (G11).
- **`npm run lint` / `npm run typecheck` do not exist** in this repository (`npm error Missing script`). Reported as
  absent, not as passing.
- **G4 is still `PENDING`.** Implementation and evidence are not gate acceptance; G2's missing official export is the
  only thing that can unblock the G3/G4 promotions.
