### The pass

`runPortfolioCycle` is one function and it refuses to skip a step:

```text
source version (vault bytes rehashed first)
  -> remember(source evidence)
  -> activateDesires()            internal state must actually be asking for work
  -> proposeGoal()
  -> openCouncil() + PROPOSER/SKEPTIC/COST arguments -> decide('SELECT')
  -> enqueueJob(dedupeKey = portfolio:<project>:<adapter>:<sourceVersion>)
  -> claimNextJob(lease + fencing token)
  -> adapter.derive()             deterministic, source-backed
  -> recordArtifact()
  -> completeJob()
  -> verify()                     a separate process, from the raw DB and vault
  -> remember(outcome)
  -> INSERT portfolio_cycles      append-only
```

### The two adapters, and what they refuse to invent

- `for_ai` produces claim candidates only. Every candidate is `NEEDS_VERIFICATION`,
  `confidence LOW`, cites its source version, and `verified_claims` is `0`. Nothing in this
  lane can create a verified claim: that needs a human, per `For-Ai/AGENTS.md`.
- `shopping_shorts` produces HOOK/BODY/CTA. A section with no line in the source is
  `NEEDS_SOURCE` with `text: null` instead of invented copy, and `published` is `false`.

## 3. Independent verification

The verifier is a different process running a different script that never imports the
adapter code. From the raw rows and the raw vault bytes it rechecks: the source version
exists, the stored bytes hash to their recorded blob hash, the artefact's canonical hash is
the one claimed, the artefact cites the requested source version and adapter, every claim
text equals the corresponding source line, every claim is still `NEEDS_VERIFICATION`,
`verified_claims === 0`, missing shorts sections are `NEEDS_SOURCE`, and `published` is
`false`. Unknown adapter kinds fail closed.

A cycle cannot be `USEFUL` unless `verified = 1` and the verifier identity is non-empty and
**different from the adapter kind** — enforced in the domain, in a trigger, and in the
independent validator.

## 5. No scale without evidence

- `BUILD`/`WATCH` requires at least one `DEMAND` row **and** one `UTILITY` row — refused in
  the API and by `trg_project_activation_needs_demand_insert/update`, so raw SQL cannot do
  it either.
- Demand and utility rows must cite a non-empty source reference and are append-only
  (no UPDATE, no DELETE).
- `portfolio_capacity.max_active` is seeded to `1` for this machine; the second project is
  refused at 1/1 in the API and in raw SQL.
- Cycle evidence is append-only. `(project_id, adapter_id, source_version_id)` is unique, so
  a replay is the same row, not a second pass.
