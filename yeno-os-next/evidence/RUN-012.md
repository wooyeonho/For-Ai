## 3. The design decision that matters

A panel is not allowed to compute truth, and it is not allowed to be trusted either.

- **Views, not code.** Every panel is one SQL view over the base tables, so a panel cannot
  drift from the ledger by having its own copy of the rules.
- **Lifecycle is recomputed, never stored.** `v_mc_approvals` derives
  `REVOKED → EXHAUSTED → EXPIRED → LIVE` from `revoked`, `uses/max_uses`, and `expires_at`
  at read time. An approval that ran out of time while nobody was looking reads `EXPIRED`
  without anything having to run.
- **A goal cannot look decided without a council behind it.** `v_mc_council` joins the
  verdict; `decision` is `NULL` unless a real verdict exists. `g8ReadSideAcceptance` fails
  if any `SELECTED`/`DONE` goal has no verdict id.
- **Read-only handle.** `mc` opens the DB with `readOnly: true`, so the surface cannot write
  even if a future panel tries. `UPDATE` through that handle throws.

### The eight tests

1. every panel resolves on a brand-new kernel, and a fresh install shows the stop **engaged**
2. the surface renders through a read-only handle, and a write through it is refused
3. the panel module contains no write statement at all (checked against the file bytes)
4. an expired approval reads `EXPIRED` and a live one reads `LIVE`, with nothing having run
5. a goal cannot read as decided without a verdict — the schema refuses the forgery, and
   with the trigger dropped the read side still refuses to draw it as decided
6. the timeline is the ledger, newest first, payload intact
7. panels are deterministic: the same ledger renders byte-identical twice
8. an unknown panel name is refused rather than invented

### The three new seeded defects

Each rewrites one view — exactly what a careless "small UI fix" would do — and the
independent validator must catch it:

| Seeded defect | Detected by |
|---|---|
| the Inbox panel quietly hides body-less items | `v_mc_inbox shows 0 of 1 row(s)` |
| every approval is drawn as `LIVE` | `APR-seeded-stale: panel says LIVE, the row means EXPIRED` |
| Settings reports the stop released while engaged | `settings shows stop 0, the table says 1` |

## 5. Rollback

Views only: `0017` adds no table and no data. Rollback is `DROP VIEW` for the eight names,
or a restore from a pre-`0017` backup; either way no row is lost. A clean clone reaches the
same surface by `migrate` alone, which `cli_migrate` in local CI exercises every run.
