## 1. What changed and why

RUN-013 built the boundary with a two-command vocabulary and checked only the emergency stop
before running a command. That is not what CLAUDE.md §5/§8 asks for: admission is the Governor's
job, and it is the Governor that has to weigh authority, the AX method class, an approval's scope
and expiry, and the budget — and record every refusal.

So the facade no longer decides anything. Each command declares what it is and `admit()` judges it:

```text
POST /command
  -> COMMANDS[name]            closed vocabulary, or 400
  -> admit(db, {...})          authority, method class, target, payload hash, cost, budget profile
       DENY EMERGENCY_STOP  -> 423
       DENY anything else   -> 403 with the reason code and the admission_attempts id
  -> domain handler + api.command.accepted event   (one BEGIN IMMEDIATE)
  -> projections catch up
```

The authority, cost and target are declared **by the command spec**, not taken from the request, so
a caller cannot lower the authority of an action by asking for a lower one.

## 2. The vocabulary now

| Command | Authority | Domain call |
|---|---|---|
| `self.remember` | A2 | `remember()` |
| `self.observe` | A2 | `observe()` |
| `inbox.promote` | A2 | `promoteInbox()` |
| `approval.revoke` | A2 | `revokeApproval()` |
| `run.cancel` | A2 | `cancelJob()` |

**Deliberately absent: granting an approval.** An approval is the Owner's signature on an external
effect, so the surface that wants to spend one must not be able to mint one. Revocation is allowed
because it only moves in the safe direction. A test asserts no command name contains `grant`, and
an independent probe confirms `approval.grant` is a `400` over the socket.

The domain rules behind each command still hold when the caller is HTTP: a title-only inbox item
comes back `promoted: false` with `title-only promotion refused`, and no project row appears.

No migration, no schema change. `migrations/0001_core.sql` untouched; **17 migrations pinned**.

## 3. Negative controls — the probes have teeth

A probe that cannot fail proves nothing. `scripts/red-team-api.mjs` now copies `src/` and
`migrations/` to a throwaway directory, deletes exactly one guard **in the copy**, starts that
patched server and asserts the matching attack succeeds:

| Negative control | Guard removed in the copy | Observed |
|---|---|---|
| `negative_control_stop_guard_leaks_when_removed` | the admission verdict check | a command on a stopped kernel is accepted `202` |
| `negative_control_token_guard_leaks_when_removed` | the `x-yeno-token` comparison | an anonymous `GET /health` answers `200` |

Production sources are never patched, and the copy is deleted in a `finally`.

## 7. NEXT_RUN

Still install-free, and the last piece of G8 that does not need a window: a **deterministic UI
contract** — a single JSON document that names every panel, every column, and every action a panel
may offer, generated from `COMMANDS` and the panel views rather than written by hand, with a test
that fails when a panel grows a column or an action the contract does not know about. That is what
makes the future Tauri shell unable to display or invoke anything the kernel has not admitted, and
it can be built and validated before Rust exists on this machine.
