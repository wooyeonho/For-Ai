## The invariant this RUN exists to prove

> a crash never produces a second external effect

The execution order is fixed: `claimNext → lease with a fencing token → claimEffect → the actual external effect →
commitEffect / abandonEffect → completeJob / failJob`. A resumed worker refuses an already-committed effect, refuses an
unresolved in-flight claim, may retry only after an explicitly recorded abandonment, cannot act after its lease expires,
cannot take a lease without a strictly newer fencing epoch, and cannot silently extend an expired one.

## What was built

1. `migrations/0012_workflow_runtime.sql` — `jobs`, `job_attempts`, `external_effects`, `artifacts`,
   `scheduler_state`, `queue_soak_cycles`, the `v_g4_acceptance` view, and 25 triggers: append-only attempts,
   immutable payload, monotonic attempt counter, terminal states final, monotonic lease epoch, lease token equals
   epoch, dead letter needs a reason, no enqueue/lease/effect while the emergency stop is engaged, immutable effect
   identity, committed effects final, commit needs evidence, A3+ effect needs its approval, immutable artifacts,
   Owner-only scheduler enable, append-only soak cycles, and a trigger that refuses to let a soak cycle call a
   duplicated effect a pass.
   Two of those triggers exist because the red-team suite found the holes first (see below):
   `trg_jobs_lease_no_steal` and `trg_jobs_lease_no_silent_extension`.
2. `src/domain/workflow.mjs` — durable enqueue with a dedupe key, `claimNextJob` (single-writer, `BEGIN IMMEDIATE`),
   exponential backoff (`1s · 2^(attempt-1)`, capped at 5 min), retry budget → `DEAD_LETTER`, deterministic cancel,
   `reclaimStuckJobs`, payload-sensitive idempotency keys, `claimEffect / commitEffect / abandonEffect`, artifacts,
   scheduler state (OFF by default), queue report, and `g4Acceptance`.
3. `assertLease` rejects a wrong holder, a stale fencing token **and an expired lease** — expiry was not checked before.
4. `scripts/queue-worker.mjs` — a real OS process that claims, performs a visible external effect, and can SIGKILL
   itself at either `after-claim` or `after-effect`, blocking after the kill request so no further JavaScript runs.
5. `scripts/queue-soak.mjs` — process-level crash soak: real child process, alternating kill points, lease expiry,
   reclaim, a fresh worker resuming, and a count of the lines the outside world actually received.
6. `scripts/red-team-queue.mjs` — 29 adversarial probes plus 6 negative controls.
7. `scripts/queue-exercise.mjs` — one real pass through the kernel ledger so G4 acceptance rests on work this OS
   did, not on scratch databases: a job that fails and succeeds after real backoff, a job that exhausts its budget
   and dead-letters, and one external effect claimed, performed once, and committed.
8. `scripts/independent-validation.mjs` — new `workflow_runtime_recomputed` check, computed from raw
   `jobs` / `job_attempts` / `external_effects` / `scheduler_state` / `queue_soak_cycles` rows, never from
   `v_g4_acceptance`, so a tampered view cannot certify itself.
9. `scripts/local-ci.mjs` — `queue_crash_soak` and `queue_red_team` are now CI steps, not things a human remembers.

## Two real defects the red-team found in my own G4

Both were live in the first implementation, and both are the kind of bug that a fencing token alone does not stop:

| Attack | Result before | Fix |
|---|---|---|
| Raw SQL sets `leased_by` to another worker without touching `lease_epoch` | **ALLOWED** — the lease was stolen while the token stayed valid | `trg_jobs_lease_no_steal`: a lease cannot change hands without a strictly newer epoch |
| A worker whose lease has already expired calls `completeJob` / `claimEffect` | **ALLOWED** — an expired holder still settled the job | `assertLease` now compares `lease_expires_at` against the clock; `trg_jobs_lease_no_silent_extension` stops the obvious workaround |

## Why the refusals and the soak are not vacuous

- Every raw-SQL probe seeds the row it attacks; a statement that changes 0 rows is `UNVERIFIABLE`, never `REFUSED`.
- Six negative controls drop the guard and re-run the same attack. All six succeed with the guard removed, so the
  suite measures guards rather than mis-aimed SQL. A dead control fails the suite.
- The soak kills a **real OS process** with SIGKILL, not a simulated failure, and counts lines in a side-effect log
  written by that process. `after-claim` must leave 0 lines and the resumed worker must refuse the unresolved claim;
  `after-effect` must leave exactly 1 line and the resumed worker must refuse to repeat it. 2 lines fails the cycle,
  and a cycle that claims otherwise is refused by the schema.
- Two new seeded defects (14 total) make the validator prove it catches a duplicated live effect and a soak cycle
  that lies about one.
