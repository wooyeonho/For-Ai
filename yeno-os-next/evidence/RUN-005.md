## 2. The G2 properties now under test

`test/intake.test.mjs`, 14 tests, all failing before the migration and the
domain code existed:

| Property | What would otherwise be taken on trust |
|---|---|
| a parsed title becomes an unresolved inbox item | that a title is not silently treated as a project |
| identical bytes, same origin → `DUPLICATE` | that re-import cannot fork state or double-count |
| identical bytes, different origin → separate version | that provenance is per source, not per byte string |
| an export with bodies recovers the matching titles | that recovery names the `source_version` it came from |
| title-only promotion refused, body+evidence allowed | that promotion needs bytes or an explicit Owner ref |
| an Owner confirmation promotes and is recorded as such | that the exception is visible instead of implicit |
| raw SQL cannot set `RECOVERED` | that the guard is in the schema, not only in JS |
| `intakes` / `recovery_attempts` append-only | that intake history cannot be rewritten after the fact |
| a failed recovery keeps a state and a next action | that failures are not silently dropped |
| `RECOVERED` without bytes refused at attempt level | that "I remember it" is not provenance |
| the named X candidate is a recorded state | that content is never guessed |
| coverage fails loudly on a forged title-only project | that the invariant is not decorative |
| an unparseable input is `REJECTED`, changes nothing | that a bad export cannot half-apply |
| an `ACCEPTED` intake without provenance is refused | that the ledger cannot claim a version it lacks |

Attempt counters are monotonic too: after one recorded failure,
`UPDATE inbox_items SET attempts = 0` is refused, so a recovery history cannot
be erased by rewinding the counter.

## 3. Independent recomputation, not a view read

`scripts/independent-validation.mjs` gained `intake_coverage_recomputed`. It does
not read `v_intake_invariant` — a wrong view would otherwise certify itself. It
recomputes from base tables: items with no next action, bodies claimed without
provenance, `RECOVERED` items with no matching attempt on the same
`source_version`, projects promoted from a title with neither body evidence nor
an Owner confirmation, re-import forks, accepted intakes with no version,
intakes pointing at a missing version, candidates claiming `FETCHED` with no
evidence. If G2 is ever `PASSED`, it additionally requires at least one
`CHAT_EXPORT` source and zero unresolved inbox items.

Two new seeded defects prove that check bites (both injected with the guarding
trigger dropped — exactly the state a stray writer or a bad restore would leave):

```text
DETECTED title_only_project_promoted — FAIL intake_coverage_recomputed — 1 projects were promoted from a title alone: PRJ-FORGED
DETECTED recovered_without_attempt   — FAIL intake_coverage_recomputed — 1 recovered items have no matching recovery attempt: IN-CLAIMED

seeded defects: 10, detected: 10, missed: 0
SEEDED_DEFECT_CHECK_PASS
```
