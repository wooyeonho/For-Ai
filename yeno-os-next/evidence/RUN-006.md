## Why the refusals are not vacuous

Two failure modes of a red-team suite are covered explicitly:

- A statement that changes 0 rows is `UNVERIFIABLE`, never `REFUSED`; every raw-SQL probe seeds the row it attacks.
- Four **negative controls** drop the guard and re-run the same attack. All four succeed with the guard removed
  (`emergency stop raw flip`, `approval use rewind`, `lease steal`, `denial record deletion`), so the suite is
  measuring guards rather than mis-aimed SQL. A dead control fails the suite.

Two new seeded defects were added to the harness: a recorded `ALLOWED` bypass and an unapproved A4 RUN both now
have to be caught by `governor_recomputed` (12/12 detected).

## A truth correction found while exercising the CLI

The `approval grant` smoke test on the canonical DB minted `APR-85b98f0c…` with `granted_by = owner` —
but the Owner never approved that push. The agent had labelled its own consent.
It was revoked immediately (`reason: minted by the agent during a CLI smoke test, not by the Owner`) and
migration 0011 closes the hole structurally: an approval now has to cite an Owner Packet file that exists on disk,
the reference cannot be repointed later, and the independent validator re-checks the file for every usable grant.
That row stays in the DB, revoked, as the record of the mistake.
