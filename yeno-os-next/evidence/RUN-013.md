## 1. Why the boundary before the window

CLAUDE.md §8 requires the Windows body to talk to the WSL brain over `127.0.0.1` only, with a
short-lived scoped token, an origin allowlist, a rate limit, schema validation, a request id and
an audit event — and requires that **every** write go `command handler → governor → transaction →
event → projection`, with no UI or provider writing to the DB.

A Tauri shell built before that boundary exists would be a shell with a direct line to the
database. So the boundary is built and attacked first. The desktop shell still needs an
Owner-approved Rust/Cargo install; that packet is `evidence/OWNER-PACKET-003.md`.

Explicitly **not** claimed here: the Tauri 2 shell, Living Body, state colours,
keyboard/accessibility, the 8GB RAM profile, push-to-talk voice, and any browser-level UI test.
G8 stays `PENDING`.

## 3. The properties that make it safe to build a window on

- **Loopback is not configurable.** `listen()` always passes `127.0.0.1`. A LAN listener would
  have to be a code change, reviewed as one.
- **No token, no answer.** A request without an exact `x-yeno-token` gets `401` before routing, so
  an unauthenticated caller cannot even learn which routes exist.
- **Origin allowlist.** `http://localhost`, `http://127.0.0.1`, `tauri://localhost` (and their
  ports). Anything else is `403`.
- **Reads cannot write.** The read routes are served from a `readOnly: true` handle over the G8
  views. A write through it throws at the SQLite layer, not at a code convention.
- **The write vocabulary is closed.** `COMMANDS` has exactly two entries today
  (`self.remember`, `self.observe`), each a call into a domain function. A test asserts the facade
  source contains no `INSERT`/`UPDATE`/`DELETE`/`DROP` — there is no raw-SQL path to smuggle into.
- **Effect and audit commit together.** `runCommand` writes the domain effect and the
  `api.command.accepted` event inside one `BEGIN IMMEDIATE`, then catches projections up. An
  accepted command and its record cannot come apart.
- **The stop closes the door for every command.** `stopEngaged` is checked before the handler
  runs, so a fresh install, a restored backup or a post-reboot kernel answers `423` to every
  command until an Owner reason releases the stop.
- **The stream is the ledger.** SSE replays from a cursor over the same append-only events, so a
  panel can never be ahead of an event nobody sent.

### The eight HTTP tests

1. loopback binding, and a request with no token is refused
2. a token is not enough — an unlisted origin is still refused, a Tauri origin is accepted
3. all eight panels serve, an invented panel is refused
4. no HTTP request reaches a write while the stop is engaged
5. an accepted command lands as an effect **and** an audit event in the same transaction
6. an unknown command cannot be smuggled in; a bad payload is refused, not guessed
7. the SSE stream carries the ledger, and a command shows up on it
8. the command vocabulary is closed, and every entry is a domain call rather than SQL
